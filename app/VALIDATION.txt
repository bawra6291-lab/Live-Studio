  start-stream arguments, duplicate queued/running tasks, and task settings that

- OBS GetReplayBufferStatus returns InvalidResourceState (604) when the optional
  replay buffer output is unavailable. That specific response is now treated as
  unavailable, not as a fatal preparation error.
- Real OBS response decoding exercised with mocked WebSocket replies. Stream,
  recording, active replay buffer and plugin output still block new starts/updates.
- Other status errors, connection failures and malformed output status still block.
- Scheduler regression: 07:25 preparation and exactly one 07:30 start succeed in
  a simulation with replay buffer unavailable. No real broadcast was created.
- Closed-OBS updater check does not launch or connect to OBS. This provides a
  path to install the fix through an older updater affected by this same check.
- Diagnostic export/startup log now use version.json instead of a stale literal.
- Full Windows live-start and updater/restart remain unverified.

Operational constraints:
- PC/app must run. Local LAN only; HTTP requires a trusted private network.
- Saving a schedule does not enable it. Pause also pauses scheduled ends/camera.
- Existing default end times remain blank. An older run never gains a new auto-end.
- Prepared plans are protected; already-started plans retain their original times.
- End/camera execution over 2 minutes late is skipped. Start allowance configurable.
- OBS ownership is checked using recorded stream binding, plugin target settings,
  output name and start timestamp inferred from duration. Changing the PC clock,
  output restart or unsupported duration reporting may refuse auto-end. This is
  not an OBS session UUID; supervise the first end and review any refusal.
- A requested platform end can partially succeed. Ambiguous writes are not replayed.
- Camera preset support is limited to ordinary positions 1–32 to avoid special
  device commands. The selected preset/patrol must already exist on the camera.
