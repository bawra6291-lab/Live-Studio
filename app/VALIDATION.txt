Live Desk v0.5.5 — validation and known limits

Passed with mocked platform/camera services in Linux:
- 106 Python tests: existing scheduler and OBS config protections; custom start
  and end times; fixed-clock and after-live camera actions; overnight end and
  preparation before midnight; one-shot start/end; failed camera does not cancel
  authorized ending; cancelled/missed/ambiguous end behavior; old-journal manual-end
  preservation; plan snapshots; enabled flags; editable grace allowance.
- Reject invalid times, overlaps, and camera service/reboot presets.
- Targeted end: exact recorded YouTube/Facebook IDs and OBS output only, changed
  broadcast binding refused, partial platform end leaves OBS for manual review,
  restarted output identity refused by duration/start timestamp check.
- Preflight failure retains enabled intent until pause; diagnostics redact known
  stored secrets and retain dated activity.
- Existing HTTP pairing/session, rate limit, Host/Origin/CSRF, local-only credential
  editing, concurrent action and settings preservation tests.
- v0.4 launch tests: normal launch has no tray/stream flags; administrator task
  invokes only configured OBS; another user, background logon, changed executable,
  start-stream arguments, duplicate queued/running tasks, and task settings that
  could time-limit/replace/stop OBS are rejected. Existing OBS is reused.
- Python compilation. JavaScript syntax/UI checks below were performed for v0.3;
  the dashboard web assets are unchanged in v0.4.
- Chromium at 1440px and 390px: custom start/end/camera-step save, persistence
  after reload, navigation with no horizontal document overflow, diagnostic file
  download, and cancelled automation confirmation. No JavaScript errors.
  Mobile schedule screenshot visually inspected.

v0.5.5 Facebook output reload:
- OBS CreateProfile may reply before frontend profile creation finishes. Poll
  GetProfileList for the new/current profile before editing the inactive file.
- Wait for the original profile to return; verify the saved FB target server,
  key and sync-start, without printing their values.
- Back up the plugin settings flushed when switching away from the original
  profile. Rollback writes only while inactive and on the temporary profile.

  File/third-party exception values are not included; restoration is not claimed

- Mock tests simulate delayed creation, creation timeout, profile-return failure,

v0.5.4 metadata filtering and Official stream binding:
- New-video metadata requests use documented videos.update snippet fields only;
  defaultAudioLanguage and blank defaultLanguage response values are not copied.
- OBS's existing secret must match a stream titled YouTube Official Livestream.
  A different title/key blocks preparation; no stream is created or key rotated.
- New broadcasts are bound to that stream and the binding is read back before
  metadata copying. Binding is checked again before sending OBS StartStream.
- Mock tests cover omitted language fields, retained binding on metadata failure,
  incorrect/unconfirmed binding, and a changed binding blocking live start.
- The user's 0.5.3 invalidVideoMetadata persists despite title/category being sent.
  The exact rejected payload is unavailable; language filtering addresses another
  request defect, but real YouTube acceptance is not confirmed by these tests.
- Existing incomplete broadcasts still need manual review; this release does not
  automatically retry them, clear failed runs, or change their scheduled times.

v0.5.3 YouTube metadata preflight:
- Read video metadata before inserting a new broadcast. Require title and categoryId
  for videos.update. If the previous video's category is absent, use the same
  program's verified reference category; do not invent a category.
- Missing/unavailable/cross-channel metadata fails before creating a broadcast.
- Mock HTTP tests cover the exact update body, category fallback, preflight failure,
  and retaining the broadcast ID without retries after a rejected metadata write.
- Existing matching schedules are not duplicated or overwritten. An existing
  incomplete schedule still requires manual review in YouTube Studio.
- The reported HTTP 400 invalidVideoMetadata could indicate a missing category;
  the actual user's request payload was not available. This patch fixes that
  known validation gap, but real YouTube acceptance still needs a supervised test.

  replay buffer output is unavailable. That specific response is now treated as
  unavailable, not as a fatal preparation error.
- Real OBS response decoding exercised with mocked WebSocket replies. Stream,
  recording, active replay buffer and plugin output still block new starts/updates.
- Other status errors, connection failures and malformed output status still block.

- Closed-OBS updater check does not launch or connect to OBS. This provides a

- Diagnostic export/startup log now use version.json instead of a stale literal.

Operational constraints:
- PC/app must run. Local LAN only; HTTP requires a trusted private network.
- Saving a schedule does not enable it. Pause also pauses scheduled ends/camera.
- Existing default end times remain blank. An older run never gains a new auto-end.
- Prepared plans are protected; already-started plans retain their original times.
- End/camera execution over 2 minutes late is skipped. Start allowance configurable.
- OBS ownership is checked using recorded stream binding, plugin target settings,
  output name and start timestamp inferred from duration. Changing the PC clock,
  output restart or unsupported duration reporting may refuse auto-end. This is
  not an OBS session UUID; supervise the first end and review any refusal.
- A requested platform end can partially succeed. Ambiguous writes are not replayed.
- Camera preset support is limited to ordinary positions 1–32 to avoid special
  device commands. The selected preset/patrol must already exist on the camera.
